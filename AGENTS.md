# AGENTS.md

## Миссия

Создать личного Telegram-помощника для приблизительного учёта калорий и КБЖУ.
Продукт ведёт дневник и даёт простые информационные подсказки, но не ставит диагнозы,
не назначает диеты и не заменяет врача или нутрициолога.

## Источники истины

1. `docs/ARCHITECTURE.md` — компоненты, контракты и ограничения.
2. `TASKS.md` — SMART-задачи, зависимости и evidence.
3. `docs/DEVELOPMENT_PLAN.md` — порядок вертикальных срезов.
4. `docs/adr/` — принятые необратимые решения.

## Неизменяемые ограничения MVP

- Один Python 3.14.7-процесс через Telegram long polling.
- Google Sheets — единственное постоянное хранилище.
- Доступ имеет только `ALLOWED_TELEGRAM_USER_ID`.
- Не добавлять БД, ORM, очередь или второй процесс без нового ADR.
- Синхронный Sheets API вызывать через `asyncio.to_thread`.
- Все операции Sheets сериализовать одним `asyncio.Lock`.
- Идемпотентность сообщения строится на `event_key = chat_id:message_id`.
- После неизвестного результата append сначала искать `event_key`, затем повторять.
- Хранить `logged_at` с offset и отдельно `local_date` в `APP_TIMEZONE`.
- JSON модели всегда валидировать Pydantic-моделью и пересчитывать итоги из позиций.
- При OpenAI передавать `store=false`; для Gemini использовать Interactions API. Не логировать
  ключи и сырые ответы любого провайдера.

## Команда из трёх агентов

- `product-architect` — ADR, сценарии, схема Sheets, формулы и SMART-декомпозиция.
- `python-integrator` — Python, aiogram, OpenAI/Gemini, Google Sheets, scheduler и Docker.
- `qa-operator` — независимые тесты, отказоустойчивость и инструкция настройки.

Конфигурации находятся в `.cursor/agents/`. Один файл одновременно имеет одного
владельца. `qa-operator` не переписывает реализацию целиком, а возвращает доказуемые
замечания или минимальный regression test.

## Рабочий цикл

1. Выбрать `TODO` в `TASKS.md` с закрытыми зависимостями.
2. Поставить `IN PROGRESS`, указать фактического владельца и дату начала.
3. Реализовать только заявленный вертикальный срез.
4. Запустить релевантные проверки и записать команды/результат в Evidence.
5. Передать изменение `qa-operator`; исправить blocker/high.
6. Поставить `DONE` только после выполнения SMART-критериев и Definition of Done.

## Инженерные правила

- Domain/application не импортируют aiogram, AI SDK или Google SDK.
- Интеграции реализуют протоколы и имеют детерминированные fake.
- Не считать номер строки Sheets идентификатором; использовать `meal_id`/`event_key`.
- Не доверять агрегатам модели; числа должны быть конечны, неотрицательны и в лимитах.
- Любое новое поведение сопровождается тестом, баг — regression test.
- Автотесты не используют живые Telegram, OpenAI, Gemini или Google Sheets.
- Не менять живую таблицу и не отправлять реальные сообщения без явного разрешения.
- Секреты не коммитить; реальные пользовательские данные не добавлять в fixtures.

## Definition of Done

- SMART-критерии задачи выполнены в её timebox либо отклонение объяснено;
- pytest, Ruff и mypy зелёные;
- ошибки, повторы и timeout покрыты пропорционально риску;
- документация и `TASKS.md` синхронизированы;
- `qa-operator` не оставил blocker/high замечаний;
- в Evidence записаны изменённые файлы, проверки и остаточные риски.

## Формат передачи

- результат и пользовательское поведение;
- изменённые файлы;
- выполненные проверки и точный результат;
- риски/вопросы;
- следующая доступная задача.
